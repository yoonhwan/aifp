Use your AI agents from your phone

AI Feature Pack is a set of tools for people who work with coding agents. Install only the packs you need. This guide starts with one of them: how to handle the agents on your home computer from your phone while you are out.

At a glance

A simple picture — your home computer is an office and the AI agents are the staff working in it. Each one has a desk of its own (a terminal session).

Your phone is the window and intercom into that office. The staff keep working while you are out; on the phone you see who is waiting for you, say a word, and put it back in your pocket.

Working remotely — in short

  1. Put the devices on one networkInstall Tailscale on the phone and the computer and both sit on the same private network. No router settings to touch.
  2. Connect over SSH from the phoneUse an SSH app such as Termius to log in to the computer. Key authentication is recommended.
  3. tmux keeps the sessionsStart your agents inside tmux sessions and they stay alive when the terminal closes or the phone connection drops.
  4. Just attach againNo need to resume a conversation. Attach to the live session and the screen is exactly where you left it.

That is the foundation. With many sessions, though, typing names on a phone to find one gets tiring. The two tools below take care of that.

tmuxc · tmm — the two to start with

This is the easiest pair in the collection, so it comes first. Open sessions with tmuxc; pick them on the phone with tmm.

On the computer · opens sessions

tmuxc

Opens an agent session in a project folder or git worktree with one line. Claude Code · Codex CLI · OMX · OpenCode · Command Code · Pi all use the same command.

  • Open, list and clean up sessions
  • Read recent output without attaching
  • Send a message to a session and confirm it arrived
  • Save before shutdown, restore after reboot
  • Fork a conversation into another session
On the phone · picks sessions

tmm

A TUI for picking among dozens of sessions (“seats”) on one screen with a cursor. No typing session names on a phone keyboard.

  • Pick a seat with the cursor and a few letters of search
  • Preview without attaching (auto-refresh)
  • Send a message to the selected seat
  • Seats waiting for you go to the top
  • Sort by most recent reply

tmuxc — everyday commands

# open an agent session in a project folder tmuxc open ~/work/my-app --name my-app --agent claude # list open sessions tmuxc list # read the last 40 lines without attaching tmuxc ask my-app 40 # send a line to a session tmuxc send my-app "Run the tests and tell me only the result" # save everything before shutdown → restore after reboot tmuxc save tmuxc restore --go

fable-team — the idea only

A harness for running several agents as a team rather than one. The details are in the repository docs; this is only the outline of the idea.

  • Roles are split. The one that breaks work down and hands it out, the one that plans, the one that builds and the one that reviews are separate sessions.
  • A piece of work is one file. What to do and when it counts as done are written down, so the work continues when the session changes.
  • Sessions pass notes to each other. Sending is not the end; arrival is confirmed.
  • Decisions that belong to a person go to the person. Deleting and anything irreversible is not done without approval.

Best looked at after tmuxc and tmm feel familiar.

Install

Repository: github.com/yoonhwan/aifp

To install tmuxc and tmm in one line, paste this into a terminal.

git clone https://github.com/yoonhwan/aifp.git && cd aifp && bash feature-pack/tmuxc/install.sh && bash feature-pack/tmm/install.sh
  • Requires macOS · bash 4+ · git · tmux · fzf (for tmm).
  • You can also leave it to your agent. After cloning, say “Read feature-pack/tmm/INSTALL.md and install it.”
  • Other packs work the same way. Start from README.md and INSTALL.md in the pack folder.

Security check

This repository is an exported copy of a private working repository. Every export scans all files against 58 patterns (keys · tokens · addresses · identifiers) and goes out only when nothing is left outside a reviewed allowlist.

0 found — no usable keys, tokens, passwords or private keys.

  • Key-shaped strings exist, but all are fake test values or placeholders in install docs.
  • Internal records and identifiers were removed. Internal operation notes are not in the copy, and personal and organization identifiers were replaced with placeholders.
  • Limits of the check: this is a pattern search, not a dedicated secret scanner.

When you install, do not write your own keys or tokens into files inside the repository folder.
